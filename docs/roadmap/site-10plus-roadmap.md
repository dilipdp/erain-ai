# EraIn Website 10+ Roadmap

Date: 2026-02-23
Launch target: 2026-02-24 (quality launch)
Benchmark target: 2026-04-15 (top-tier global class)

## Objective

Ship a premium, high-conversion, trust-heavy website that is:

- Launch-ready by 2026-02-24
- Distinct in category positioning
- Strong in proof, governance, and ROI messaging
- Scalable to true top-tier benchmark over the next 4-8 weeks

## Success Metrics

- Hero engagement: at least 55% scroll-through to section 2
- Primary CTA click-through: at least 4%
- Sample report click-through: at least 2.5%
- Request assessment conversion: at least 1.5%
- Lighthouse targets: 95+ Performance, 100 Accessibility, 100 SEO on core pages

## Phase Plan

### Phase 0 - Baseline Lock (2026-02-23)

Scope:

- Remove old hero asset dependency
- Lock a clean current baseline
- Create roadmap and delivery structure

Done when:

- No page references deleted hero assets
- Build passes
- Baseline commit created

### Phase 1 - Premium System (2026-02-23)

Scope:

- Tighten global typography rhythm
- Upgrade nav/header depth and states
- Improve shared button/card system consistency
- Improve motion hierarchy and reduced-motion parity

Done when:

- Visual consistency improves across all pages using BaseLayout
- No regressions on mobile nav and CTA buttons
- Build passes

### Phase 2 - Homepage Authority (2026-02-23)

Scope:

- Add high-trust proof modules on homepage
- Strengthen narrative from auditability -> governance -> ROI
- Improve fold-to-fold flow so no dead zones remain

Done when:

- Homepage has no weak/empty sections
- Messaging supports enterprise decision-makers
- Build passes

### Phase 3 - Conversion and Trust Hardening (2026-02-24)

Scope:

- Improve request flow friction points
- Strengthen trust/compliance cues
- Add stronger conversion loops (repeat CTA and objections handling)

Done when:

- Contact and request flow is consistent and low-friction
- Trust statements are concrete and not generic
- Build passes

### Phase 4 - Performance and QA Gate (2026-02-24)

Scope:

- Check for broken links and stale references
- Validate responsive layouts
- Validate content density and typography at multiple viewport sizes

Done when:

- Build passes
- Manual smoke checks pass
- Launch sign-off committed

## Execution Rules

- One phase = one commit minimum
- No mixed commits with unrelated docs or code
- Build must pass before every phase commit
- Keep copy evidence-first and specific
