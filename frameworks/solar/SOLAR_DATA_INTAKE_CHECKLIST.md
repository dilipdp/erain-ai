# SOLAR DATA INTAKE CHECKLIST
Version: 1.0  
Purpose: Define strict data collection standards before Solar Audit begins  
Classification: Internal – Governance Critical  

---

# CORE RULE

We do NOT begin analysis without structured, validated data.

Incomplete data = distorted ROI  
Distorted ROI = damaged trust  

If required inputs are missing → pause engagement.

---

# 1 — BASIC PLANT INFORMATION (MANDATORY)

Client must provide:

[ ] Plant capacity (DC kWp / MWp)  
[ ] Commissioning date  
[ ] Inverter make + model + count  
[ ] HT or LT configuration  
[ ] Transformer rating (if HT)  
[ ] Plant layout (single line diagram if available)  

Reject analysis if:
• Capacity mismatch across documents  
• Configuration unclear  

---

# 2 — GENERATION DATA (MINIMUM 12 MONTHS)

Required:

[ ] Monthly generation (kWh) – last 12 months  
[ ] Daily generation logs (preferred)  
[ ] SCADA export (CSV / Excel format)  
[ ] Inverter-wise generation (if available)  

Validation:

[ ] Cross-check monthly totals vs invoice export  
[ ] Check for missing months  
[ ] Identify abnormal spikes or zero days  

If less than 6 months data → mark as limited-confidence audit.

---

# 3 — IRRADIANCE DATA (WEATHER NORMALIZATION)

Required:

[ ] On-site POA irradiance (preferred)  
OR  
[ ] Nearest reliable weather station data  

Validation:

[ ] Confirm unit consistency (kWh/m²)  
[ ] Confirm time alignment with generation data  
[ ] Identify sensor downtime  

No weather normalization → no PR-based monetization.

---

# 4 — TARIFF & REVENUE DATA

Required:

[ ] Power Purchase Agreement (PPA) copy OR  
[ ] DISCOM tariff structure  
[ ] Last 6 electricity invoices  
[ ] Net vs gross billing clarity  

Validation:

[ ] Confirm export tariff  
[ ] Confirm captive consumption rate (if applicable)  
[ ] Validate currency + tax inclusion  

Tariff must be invoice-backed.

---

# 5 — DOWNTIME & MAINTENANCE RECORDS

Required:

[ ] Maintenance logs (12 months)  
[ ] Fault register  
[ ] Breakdown reports  
[ ] Preventive maintenance schedule  

Validation:

[ ] Check downtime hours per incident  
[ ] Check response time vs SLA  
[ ] Identify repeat faults  

If no maintenance logs → downgrade downtime confidence level.

---

# 6 — CLEANING & SOILING RECORDS

Required:

[ ] Cleaning frequency schedule  
[ ] Cleaning logs  
[ ] Seasonal cleaning variation  

Validation:

[ ] Check consistency across months  
[ ] Cross-reference with generation dips  

If cleaning undocumented → treat soiling recovery conservatively.

---

# 7 — HT EXPORT DATA (IF HT PLANT)

Required:

[ ] Energy generated (inverter total)  
[ ] Energy exported (meter reading)  
[ ] Transformer technical specifications  
[ ] Protection relay logs (if available)  

Validation:

[ ] Compare generated vs exported  
[ ] Benchmark transformer loss %  
[ ] Check metering mismatch  

Export gap must be engineering-validated.

---

# 8 — VENDOR CONTRACTS

Required:

[ ] O&M contract copy  
[ ] SLA response time commitments  
[ ] Penalty clauses  

Validation:

[ ] Confirm response time terms  
[ ] Confirm uptime guarantees  
[ ] Identify penalty enforceability  

Do not assume SLA recovery without contract proof.

---

# 9 — FINANCIAL CONTEXT

Required:

[ ] Engagement cost estimate  
[ ] O&M annual cost  
[ ] Major repair cost history  
[ ] Capex upgrades in past 24 months  

Purpose:

Enable realistic ROI and payback modeling.

---

# 10 — DATA FORMAT REQUIREMENTS

Accepted formats:

• CSV  
• Excel (.xlsx)  
• Structured SCADA export  

Not acceptable:

• Screenshots  
• WhatsApp photos  
• Manual typed summaries  

All files must be original exports.

---

# 11 — DATA QUALITY GRADING

After intake, assign grade:

A — Complete + consistent  
B — Minor gaps  
C — Partial data  
D — Insufficient for ROI modeling  

If grade C or D:
Present limitations clearly before audit.

---

# 12 — CONFIDENTIALITY PROTOCOL

Before intake:

[ ] NDA signed  
[ ] Storage folder created  
[ ] Access restricted  
[ ] File naming convention applied  
[ ] Version tracking enabled  

Never mix client folders.

---

# 13 — INTAKE COMPLETION DECLARATION

Before analysis begins:

[ ] All mandatory sections received  
[ ] Data validated  
[ ] Tariff confirmed  
[ ] Weather source confirmed  
[ ] Double-count risk assessed  

If unchecked → delay audit start.

---

# DISCIPLINE RULE

Do not rush intake to impress client.

Precise intake = defensible outcome.  
Defensible outcome = brand authority.

---

This checklist protects:

• Financial integrity  
• Engineering credibility  
• CFO defensibility  
• Legal trust  
• Reputation stability  

Solar audit begins only after intake control is established.
