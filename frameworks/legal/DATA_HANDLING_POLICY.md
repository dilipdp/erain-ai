

# ERAIN AI – DATA HANDLING & PROTECTION POLICY
Version: 1.0  
Classification: Legal – Internal Governance  
Owner: Founder  
Effective Date: ____________________

---

# 1. PURPOSE

This Data Handling & Protection Policy defines how EraIn AI collects, stores, processes, accesses, protects, and disposes of client data.

This policy applies to:

• All client documents  
• Operational data sets  
• Financial records  
• KPI exports  
• Audit outputs  
• Internal working files derived from client data  

This policy is mandatory for every engagement.

---

# 2. CORE PRINCIPLES

EraIn operates under five principles:

1. Minimum Necessary Access  
2. Purpose-Limited Usage  
3. Controlled Storage  
4. Traceable Access  
5. Secure Disposal  

Data is never collected casually.
Data is collected only when structure is ready.

---

# 3. DATA CLASSIFICATION LEVELS

All incoming data must be classified:

## Level 1 – Public
Non-sensitive material approved for public release.

## Level 2 – Internal
Non-public but low-risk operational material.

## Level 3 – Confidential
Financial, operational, vendor, plant, or performance data.

## Level 4 – Restricted
Highly sensitive:
• Payroll  
• Customer lists  
• Bank statements  
• Trade secrets  
• Source code  
• Legal records  

Restricted data requires additional access approval.

---

# 4. DATA COLLECTION RULES

Before collecting client data:

✔ NDA must be signed  
✔ Engagement scope must be defined  
✔ Data request list must be documented  
✔ Storage environment must be ready  

EraIn never collects undefined data.

---

# 5. STORAGE POLICY

Client data must:

• Be stored in designated secure folders  
• Not be stored on personal devices without encryption  
• Not be shared via unsecured messaging platforms  
• Be separated by client directory  
• Be labeled with standardized naming conventions  

Example structure:

/clients/
   /Client_Name/
       /raw_data/
       /processed_data/
       /audit_outputs/
       /final_reports/

---

# 6. ACCESS CONTROL

Access must be:

• Role-based  
• Limited to engagement members  
• Revoked after engagement closure  

Founder retains audit visibility across engagements.

No third-party sharing without written approval.

---

# 7. DATA PROCESSING RULES

Derived models, calculations, and dashboards:

• Must not expose raw sensitive data externally  
• Must not be reused across clients without anonymization  
• Must not be stored in public repositories  

Internal reuse is permitted only after anonymization.

---

# 8. DATA RETENTION

Unless otherwise agreed:

• Raw client data retained for 12 months  
• Final reports retained for 3 years  
• Audit artifacts retained for compliance defense  

After retention period:

• Data must be deleted or archived securely  
• Client may request early deletion in writing  

---

# 9. DATA BREACH RESPONSE

If unauthorized access occurs:

1. Immediate containment  
2. Access suspension  
3. Root cause analysis  
4. Client notification within 72 hours  
5. Preventive remediation steps  

All breaches must be documented.

---

# 10. ENGAGEMENT CLOSURE

Upon project completion:

✔ Access rights reviewed  
✔ Sensitive data archived or deleted  
✔ Delivery artifacts separated from raw files  
✔ Risk register updated  

---

# 11. POLICY ENFORCEMENT

Violation of this policy may result in:

• Engagement suspension  
• Contract termination  
• Legal action
