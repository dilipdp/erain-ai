

# EraIn ROOT CAUSE REGISTRY™

> The intelligence backbone that connects Leakage → Diagnosis → Action → ROI Proof.

---

# 1. Purpose

The Root Cause Registry is a structured knowledge system that:

- Maps recurring operational problems to verified root causes
- Prevents symptom-based firefighting
- Enables quantified recovery planning
- Standardizes diagnosis across industries
- Feeds directly into the ROI Ledger Model™

This ensures EraIn never recommends surface-level fixes.

---

# 2. Root Cause Hierarchy Model

Every issue must be mapped using a 4-level structure:

LEVEL 1 – Symptom (What is visible)
LEVEL 2 – Leakage Category (Where value is lost)
LEVEL 3 – Structural Root Cause (Why it is happening)
LEVEL 4 – System Failure Type (Which governance gap allowed it)

---

# 3. Universal Root Cause Categories

These apply across manufacturing, services, logistics, solar, retail, etc.

## A. Ownership Failure

- No single accountable owner
- Shared responsibility ambiguity
- Escalation paths undefined
- KPI without ownership mapping

## B. Decision Latency

- Data delayed
- Approval bottlenecks
- Manual reporting loops
- Leadership review frequency too low

## C. Process Design Defect

- Poor handoffs
- Rework loops
- No checkpoint gates
- Weak SOP enforcement

## D. Incentive Misalignment

- Teams rewarded for activity, not outcomes
- Cost center vs profit center conflict
- Vendor incentives misaligned

## E. Measurement Failure

- KPI exists but not tracked weekly
- Lag indicators only
- No leading signals
- No ROI attribution model

## F. Capacity Constraint

- Labor overload
- Machine downtime
- Vendor bottleneck
- Working capital limitation

## G. Governance Gap

- No audit trail
- No review cadence
- Weak compliance mapping
- No exception discipline

# 4. Root Cause Coding System

Each root cause must be tagged:

Format:

RC-[Category Code]-[Industry Tag]-[Sequential ID]

Example:

RC-OWN-MFG-001
RC-MEA-LOG-004
RC-DEC-SVC-012

Category Codes:

OWN = Ownership
DEC = Decision
PRC = Process
INC = Incentive
MEA = Measurement
CAP = Capacity
GOV = Governance

# 5. Diagnosis Protocol (Used During Audit)

When a leakage is identified:

Step 1 – Describe Symptom in measurable terms
Step 2 – Quantify Financial Impact
Step 3 – Ask “Why?” five times
Step 4 – Map to Root Cause Category
Step 5 – Validate with data + interviews
Step 6 – Assign Owner + Fix Timeline
Step 7 – Link to ROI Ledger entry

No recommendation is allowed without Root Cause classification.

---

# 6. Root Cause → Action Mapping

Each root cause must have predefined corrective pathways.

Example:

Root Cause: Decision Latency (DEC)
Fix Type:
- Weekly review cadence
- KPI dashboard automation
- Escalation trigger rule

Root Cause: Ownership Failure (OWN)
Fix Type:
- Named owner
- Defined escalation ladder
- Performance linkage

Root Cause: Measurement Failure (MEA)
Fix Type:
- Define leading KPI
- Weekly tracking
- ROI tagging

# 8. Root Cause Confidence Scoring

Each root cause must have confidence level:

High – Supported by data + interviews
Medium – Supported by trend + partial validation
Low – Hypothesis pending validation

No major execution plan proceeds without Medium or High validation.
