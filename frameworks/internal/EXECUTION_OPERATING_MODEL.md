# 3. CLIENT ENGAGEMENT FLOW (CONTROL TOWER VIEW)

## Phase 1 — Internal Readiness (Before Data Collection)

✔ Industry framework customized  
✔ KPI library mapped  
✔ Sample output pack prepared  
✔ Risk register template ready  
✔ Execution tracker template ready  
✔ Confidentiality protocol defined  

NO DATA IS COLLECTED UNTIL THIS IS COMPLETE.

---

## Phase 2 — Data Intake

- Data request structured (never open-ended)
- Only essential datasets requested
- All data logged in intake register
- Missing data documented explicitly

Output:
→ Data completeness status
→ Data quality risk note
→ Assumption log

---

## Phase 3 — Audit Analysis

Steps:
1. Baseline current state
2. Identify leakage clusters
3. Quantify top 20% value drivers
4. Root-cause map top 3 leaks
5. Validate with client discussion
6. Finalize quantified findings

Nothing is shared without:
- Internal logic check
- Assumption validation
- Financial consistency cross-check

---

## Phase 4 — Recommendation Discipline

Every recommendation must include:

- Problem statement
- Root cause
- Quantified impact
- Owner
- Timeline
- KPI affected
- Risk factors
- Verification method

If any element is missing → Not delivery ready.

# 4. INTERNAL WEEKLY RITUAL (FOUNDER CONTROL LOOP)

Every week (fixed time):

1. Review all active clients
2. Check:
   - Is execution tracker updated?
   - Are owners accountable?
   - Are KPIs moving?
   - Are risks escalating?
3. Identify:
   - Red zones
   - Stalled actions
   - Data gaps
4. Document:
   - 3 highest risk items
   - 3 highest leverage improvements
5. Prepare next client review deck

No week is skipped.

# 5. ESCALATION PROTOCOL

If:
- Data is incomplete
- Owner is not responding
- KPIs not improving
- Timeline slipping
- Trust risk detected

Then:

Step 1: Document issue  
Step 2: Notify primary stakeholder  
Step 3: Define recovery plan  
Step 4: Track in risk register  

Escalation is documented, never emotional.
