## 0) Why this exists
EraIn must never “invent per client.”
This document is the **universal operating system** for every engagement — manufacturing, services, logistics, solar, retail, and any future sector.

**If a step is not defined here, we do not do it with client data.**

Core rule:
**Truth → Decisions → Execution → Impact** (with proof and audit trail).

## 1) Engagement Architecture (Universal)
Every engagement is the same spine with industry extensions.

### 1.1 The Spine (non‑negotiable)
1. **Pre‑Intake Gate** (readiness + legal + storage)
2. **Intake** (documents + interviews + access map)
3. **Reality Map** (what is actually happening)
4. **Leakage Map** (where value is leaking)
5. **Root Cause Map** (why it’s happening)
6. **Quantification** (₹/$ impact + recovery potential)
7. **Decision Pack** (what to do first, and why)
8. **Execution Install** (owners + cadence + checkpoints)
9. **Validation** (proof of change + attribution)
10. **Hand‑off / Retain** (OpsMind / Impact AI)

### 1.2 Industry Extension Layer
Each industry adds:
- KPI pack
- leakage patterns
- root cause patterns
- typical data sources
- standard charts + artifacts

**Naming convention:**
- Universal: `frameworks/core/*`
- Industry: `frameworks/<industry>/*`
- Toolkit: `frameworks/toolkit/*`

## 3) Intake System (Day 0 → Day 2)
### 3.1 Intake Goals
- Build a **single source of truth** dataset and reality map.
- Confirm the **operating boundaries** (sites, teams, scope).
- Identify data gaps early without stalling.

### 3.2 Intake Inputs (universal)
1. **Org + Scope**
   - site list, functions, headcount by function, key roles
2. **Financial**
   - P&L summary, cost heads, revenue streams, major vendors
3. **Operational**
   - SOPs, process maps (if any), shift schedules
4. **Systems**
   - ERP/Tally/Excel sheets, trackers, logs
5. **Performance**
   - KPIs currently tracked + cadence
6. **Constraints**
   - compliance, safety, customer SLAs, legal

### 3.3 Intake Interviews (minimum)
- Founder/CEO/Plant head
- Finance head
- Ops head
- One frontline supervisor

Output:
- **Access Map** (who owns what)
- **Data Map** (what exists where)
- **First Reality Sketch**

---

## 4) Reality Mapping (Truth Layer)
### 4.1 Reality Map Definition
A short, factual description of:
- how work flows
- where decisions happen
- where delays/defects occur
- where ownership breaks

### 4.2 Reality Map Outputs
- Process flow (high level)
- Constraint list
- “Reality vs Report” mismatch list

Rules:
- Use **client language**, not AI jargon.
- Mark assumptions clearly.

---

## 5) Leakage Mapping (Value Loss Layer)
### 5.1 Leakage Categories (Universal)
1. **Time leakage** (delays, idle, waiting)
2. **Quality leakage** (rework, defects, scrap)
3. **Cost leakage** (waste, overconsumption, bad procurement)
4. **Revenue leakage** (churn, penalties, missed billing)
5. **Decision leakage** (wrong priorities, late decisions)
6. **Ownership leakage** (no owner, weak escalation)
7. **System leakage** (manual work, duplicate work, bad tools)

### 5.2 Leakage Evidence Rules
Each leakage must have:
- evidence source
- frequency
- scope (site/team)
- estimated impact band (Low/Med/High)

Output:
- **Leakage Register** (ranked)

---

## 6) Root Cause Mapping (Why Layer)
### 6.1 Root Cause Model (5 Layers)
For each top leakage, map:
1. **Symptom**
2. **Proximate cause** (immediate)
3. **System cause** (process/tool)
4. **Behavior cause** (habits/incentives)
5. **Governance cause** (cadence/ownership/controls)

### 6.2 Root Cause Proof Rule
No root cause is accepted unless:
- it explains the pattern across time
- it matches observed reality
- it connects to an owner/action

Output:
- **Root Cause Cards** (top 3–7)

---

## 7) Quantification (ROI / Impact Layer)
### 7.1 Quantification Principle
We do not sell AI.
We quantify recovered value.

### 7.2 Impact Types
- **Direct** (₹ saved, revenue recovered)
- **Indirect** (time saved → capacity unlocked)
- **Risk** (penalty/incident probability reduction)

### 7.3 ROI Attribution Model
For each action:
- baseline metric
- target metric
- time horizon
- attribution confidence (High/Med/Low)
- proof method (before/after, control group, audit trail)

Output:
- **Impact Table** + **Recovery Potential**

---

## 8) Decision Pack (Executive Layer)
### 8.1 Decision Pack Contents
- Top 10 findings (ranked)
- Top 3 root causes
- Top 10 actions (30/60/90)
- Owner map
- Impact estimate
- Risks + assumptions

### 8.2 Decision Rule
We recommend only what the client can execute with owners.

Output:
- Executive PDF / Deck

---

## 9) Execution Install (Cadence Layer)
### 9.1 Execution System
- Owner assignment (single threaded owner)
- Weekly cadence meeting
- Action tracker
- Escalation ladder (L1 → L3)
- Decision log

### 9.2 Cadence Templates (minimum)
- Weekly Ops Review
- Weekly Finance/Impact Review
- Monthly Leadership Review

Output:
- **Execution Calendar** + **Tracker** + **Governance Rules**

---

## 10) Validation (Proof Layer)
### 10.1 Proof Standard
Every claimed improvement must have:
- timestamp
- metric change
- evidence link
- owner confirmation

### 10.2 Audit Trail
All changes must be traceable:
- what changed
- who changed
- why
- when

Output:
- **Impact Proof Pack**
