# EraIn AI — Client Data Request Checklist (Controlled Collection v1.0)

> Purpose: Define exactly what data we request, why we request it, and when we request it — to avoid over-collection, confusion, and trust loss.

---

## 0. Core Principle (Non‑Negotiable)

We do NOT collect data until:
- Audit scope is defined
- NDA (if required) is signed
- Data boundaries are documented
- Client understands what will and will NOT be accessed

We collect the minimum required to:
1. Detect value leakage
2. Quantify impact
3. Build execution plan

Nothing more.

---

# LEVEL 1 — Free Audit (Lightweight Data Only)

Objective: High-signal diagnosis without sensitive exposure.

### Required (Summary-Level Only)

- Last 6–12 months revenue summary (monthly totals)
- Cost summary by major category (monthly totals)
- Org structure (roles + reporting lines)
- Process overview (how work flows end-to-end)
- Top 3 current problems leadership sees

### NOT Required (at this stage)

- Customer names
- Vendor contracts
- Detailed payroll
- Bank statements
- Individual employee data
- Raw transactional dumps

Output:
- Ranked findings
- Risk heatmap
- 30/60/90 roadmap

---

# LEVEL 2 — Pro Audit (Structured Diagnostic Data)

Objective: Root cause + quantified leakage.

### Finance
- Revenue by segment/product/site
- Direct cost breakdown
- Overhead categories
- Margin by segment (if available)
- Working capital metrics

### Operations
- Production / service throughput data
- Downtime / delay logs
- SLA performance
- Rework / defect rates
- Lead time data

### Sales / Growth
- Funnel metrics
- Conversion ratios
- Churn / retention numbers
- Customer complaint themes (not names)

### Procurement
- Vendor category spend
- Price variance
- Approval process structure

Still NOT Required (unless justified):
- Personal employee performance files
- Legal disputes documentation
- Sensitive HR records
- Individual bank entries

Output:
- ₹ / $ quantified leakage
- Root-cause map (Top 3 issues)
- 90-day execution blueprint
- Ownership + cadence map

---

# LEVEL 3 — OpsMind Deployment (Controlled Access)

Only after client approval.

Possible Access Types:
- Read-only dashboards
- Scheduled reports export
- API access (limited scope)
- ERP / Tally / Excel structured extracts

Security Controls:
- Role-based access
- Time-bound access tokens
- Access log maintained
- Data storage boundaries defined
- Client can revoke anytime

# DATA ETHICS DECLARATION

EraIn AI commits:
- No resale of data
- No model training on proprietary client data
- No data sharing without written consent
- Minimal retention policy
- Secure deletion upon termination

---

# INTERNAL USE CHECKLIST (Before Asking Client)

Before requesting data, confirm:

[ ] Do we know exactly why we need it?
[ ] Is there a lighter version we can request instead?
[ ] Have we defined the output clearly?
[ ] Is this data necessary for quantified impact?
[ ] Would we be comfortable if our own company was asked the same?

If any answer is NO → Do not request yet.
