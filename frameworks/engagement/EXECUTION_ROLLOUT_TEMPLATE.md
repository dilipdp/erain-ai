

# ERAIN EXECUTION ROLLOUT TEMPLATE

Version: 1.0  
Owner: EraIn AI  
Applies To: All Industries / All Clients  

---

# 1. PURPOSE

This document converts a completed EraIn Audit (Free or Pro) into a structured, accountable execution program.

No rollout begins without:
- Ranked leak summary
- Quantified impact (if Pro)
- Named client sponsor
- Defined 30/60/90 priorities

Execution is never abstract. It is owned, measured, and time-bound.

---

# 2. ROLLOUT STRUCTURE OVERVIEW

Execution follows a 4-layer structure:

1. Reality Baseline (Verified Snapshot)
2. Priority Stack (Top 3–5 Value Leaks)
3. Owner + Cadence Installation
4. Impact Measurement Loop

---

# 3. PHASE 0 — EXECUTIVE ALIGNMENT (Week 0)

Objective: Confirm scope, ownership, and decision authority.

Required:
- Executive Sponsor (single accountable authority)
- Operational Champion (day-to-day coordinator)
- Finance Contact (for impact validation)

Deliverables:
- Confirmed Top 3 Priorities
- Confirmed ROI targets
- Agreed review cadence (weekly / biweekly)

No alignment → No rollout.

---

# 4. PHASE 1 — REALITY BASELINE (Week 1–2)

Objective: Establish clean baseline before change.

Activities:
- KPI validation
- Data consistency checks
- Leak confirmation
- Root-cause verification

Outputs:
- Baseline metrics locked
- Ownership map documented
- Execution board created

This becomes the reference point for all impact claims.

---

# 5. PHASE 2 — EXECUTION INSTALLATION (Week 2–6)

For each priority:

Define:
- Problem statement
- Financial impact estimate
- Root cause
- Responsible owner
- Weekly measurable indicator

Install:
- Weekly review cadence
- Escalation pathway
- Exception log
- Accountability tracker

No initiative exists without a named owner.

---

# 6. PHASE 3 — MONITORING LOOP (Ongoing)

Every week:
- KPI delta vs baseline
- Blockers
- Escalations
- Decision required

Every month:
- Impact quantified
- Lessons captured
- System refinement

Impact must be attributable.

---

# 7. ROI PROOF STRUCTURE

Each improvement must answer:

1. What changed?
2. Why did it change?
3. Who owned it?
4. What is the financial delta?
5. Is it sustained or temporary?

If ROI cannot be proven, it cannot be claimed.

---

# 8. CLIENT EXECUTION DASHBOARD FORMAT

Each client gets a structured dashboard containing:

- Top 5 Priorities
- Baseline KPI
- Current KPI
- Owner
- Status (Green / Amber / Red)
- Financial delta
- Next checkpoint date

---

# 9. ESCALATION PROTOCOL

If:
- Owner misses 2 cycles
- KPI worsens for 3 consecutive periods
- Sponsor disengages

Then:
- Executive escalation triggered
- Root-cause reassessment
- Cadence reset

Execution discipline is non-negotiable.

---

# 10. COMPLETION CRITERIA

A rollout cycle is considered complete when:

- Top 3 leaks reduced or eliminated
- Financial recovery meets agreed threshold
- Accountability loop becomes self-sustaining
- Executive sponsor signs off

Then:
- Expand to next priority stack
OR
- Transition to OpsMind monthly cadence

---

# 11. UNIVERSAL PRINCIPLES

- Truth before speed
- Ownership before automation
- Measurement before claims
- Impact before expansion
