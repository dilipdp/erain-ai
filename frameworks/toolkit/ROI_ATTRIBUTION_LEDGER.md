---

# 0. PURPOSE

The ROI Attribution Ledger is the single source of truth for:

• All quantified impact claims
• All recovered value calculations
• All ROI statements
• All executive financial summaries

If impact is not logged here → it does not exist.

No deck. No report. No proposal may reference value without an RAL entry.

---

# 1. CORE PRINCIPLE

Truth → Formula → Evidence → Attribution → Proof → Governance

Every impact must pass 6 gates:

1. Defined Leakage Category
2. Registered Formula_ID
3. Verified Input Snapshot
4. Evidence Reference
5. Attribution Level
6. Executive Sign-off (when required)

---

# 2. LEDGER ENTRY STRUCTURE

Each impact record must include:

• Ledger_ID
• Client_Name
• Industry
• Engagement_Phase
• Leakage_Category
• KPI_ID
• Formula_ID
• Baseline_Value
• Current_Value
• Improvement_Value
• Financial_Impact_Value
• Unit (₹ / $ / % / Months)
• Attribution_Level (1–4)
• Confidence_Score (Low / Medium / High / Verified)
• Evidence_ID
• Evidence_Location
• Assumptions
• Sensitivity_Notes
• Snapshot_Date
• Calculation_Date
• Owner
• Review_Status
• Executive_Approval_Status

No missing fields allowed.

---

# 3. ATTRIBUTION LEVELS

Level 1 — Correlated Impact
• Improvement observed
• Direct causal link not proven
• Used for directional insight only

Level 2 — Supported Attribution
• Improvement linked to specific action
• Supporting evidence exists
• Some external influence possible

Level 3 — Strong Attribution
• Clear causal chain
• Before/after evidence
• Minimal external distortion

Level 4 — Verified Financial Proof
• Controlled validation
• Multi-cycle confirmation
• Executive validation
• Auditable trail

Only Level 3+ may be used in ROI claims.

---

# 4. CONFIDENCE SCORING

Low → Assumptions dominant
Medium → Mixed evidence
High → Strong data support
Verified → Multi-period validated

Confidence and Attribution are separate metrics.

---

# 5. FORMULA CONTROL RULE

Every financial impact must reference:

• Formula_ID (from MFR)
• Variable Definitions
• Snapshot Data

If Formula_ID missing → entry invalid.

---

# 6. SNAPSHOT DISCIPLINE

Each calculation must capture:

• Baseline snapshot date
• Current snapshot date
• Time interval
• Data source

No rolling averages without disclosure.

No blended baselines.

---

# 7. DOUBLE-COUNT PROTECTION

Before logging impact:

Check if:
• Same leakage already logged
• Upstream/downstream duplication exists
• Margin and revenue both counted incorrectly

If overlap risk exists:
→ Flag as "Impact Interaction Risk"
→ Adjust or isolate attribution

---

# 8. INDUSTRY EXTENSION RULE

Manufacturing, Logistics, Solar, Services may:

• Add sub-ledger fields
• Add industry-specific evidence types
• Add operational context notes

But must preserve universal structure.

---

# 9. EXECUTIVE SUMMARY RULE

Any CXO report must summarize:

• Total Recovered Value
• By Leakage Category
• By Attribution Level
• By Confidence Score
• ROI % (Formula F-010)
• Payback Period (Formula F-011)

All numbers must trace to Ledger_ID.

---

# 10. GOVERNANCE & REVIEW

Weekly:
• Update new entries
• Review attribution integrity

Monthly:
• Validate confidence scoring
• Audit random entries

Quarterly:
• Executive review
• Attribution upgrade/downgrade review

---

# 11. PROHIBITED PRACTICES

• Inflated assumptions
• Unregistered formulas
• Forward-looking ROI disguised as achieved impact
• Combining unrelated improvements
• Ignoring negative offsets

Violations reduce brand integrity score.

---

# 12. ERAIN FINANCIAL CONSTITUTION

No revenue claim without proof.

No proof without formula.

No formula without registry.

No registry without governance.
