

# ROOT CAUSE MAPPING TEMPLATE

Version: 1.0  
Owner: EraIn Universal Execution Core  
Purpose: Convert audit findings into verified root causes, accountable execution plans, and measurable ROI.

---

# 1. ROOT CAUSE PRINCIPLE

EraIn does NOT fix symptoms.
We identify:

Finding → Contributing Factors → Structural Cause → Control Failure → Owner Gap → System Gap

Only structural causes are allowed into execution planning.

---

# 2. ROOT CAUSE CLASSIFICATION MODEL

Every finding must be tagged under ONE primary structural cause:

### A. Process Failure
- Undefined workflow
- Broken handoff
- No escalation rule
- No SLA
- No documented standard

### B. Ownership Failure
- No accountable owner
- Shared ownership confusion
- Decision latency
- Escalation avoidance

### C. Measurement Failure
- KPI not defined
- KPI not monitored
- KPI monitored but not acted upon
- Lagging metrics only

### D. Incentive Misalignment
- Wrong reward structure
- No penalty for leakage
- Target encourages wrong behavior

### E. Skill / Capability Gap
- Training gap
- Hiring mismatch
- Overload / under-capacity

### F. System / Tool Gap
- Manual dependency
- Disconnected systems
- Reporting delay
- No visibility layer

### G. Governance Failure
- No review cadence
- No audit trail
- No approval control
- No compliance check

---

# 4. 5-WHY VALIDATION (MANDATORY)

Every root cause must pass 5 levels of why.

Example:

Problem: High logistics penalties
Why 1: Deliveries late
Why 2: Route planning inconsistent
Why 3: No standard dispatch cutoff time
Why 4: No owner assigned for dispatch discipline
Why 5: Dispatch SLA not part of performance review

Root Cause: Ownership + Process failure

If the 5th why is still vague → root cause is incomplete.

---

# 5. CONTROL FAILURE IDENTIFICATION

Every structural cause must identify:

- Which control should have prevented this?
- Why did that control fail?
- Is it missing, weak, or ignored?

Control Types:
- Preventive
- Detective
- Escalation
- Governance

No control → System gap.
Ignored control → Accountability gap.

---

# 6. FIX TYPE CLASSIFICATION

Every root cause must map to ONE of the following execution types:

1. Process Redesign
2. Ownership Realignment
3. KPI Installation
4. Automation / System Upgrade
5. Incentive Redesign
6. Governance Cadence Install
7. Training Intervention

---

# 7. EXECUTION LINKAGE BLOCK

Every approved root cause must produce:

- Defined Owner (single accountable)
- Weekly Cadence
- 30/60/90 Milestones
- KPI to measure recovery
- Financial Recovery Target
- Review checkpoint

No execution block → Root cause cannot move to plan.

---

# 8. ROOT CAUSE QUALITY CHECK

A valid root cause must:

✔ Be structural (not behavioral blame)  
✔ Be fixable within organization control  
✔ Have measurable impact  
✔ Map to execution owner  
✔ Produce a financial recovery path  

If not, it is still a symptom.

---

# 9. ROOT CAUSE MATURITY INDEX

Score each root cause clarity (1–5):

1 = Surface symptom  
2 = Partial structural view  
3 = Clear structural cause  
4 = Structural + control gap defined  
5 = Structural + control + owner + measurable impact defined

Minimum required for execution: 4
